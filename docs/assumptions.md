# 合理假设记录

## 1. 业务假设

### 1.1 数据假设
- **学生数据格式**: 假设学生数据包含学号、姓名、班级、专业、年级等基本信息
- **成绩数据范围**: 假设所有成绩均为0-100分的整数或一位小数
- **课程数据结构**: 假设每门课程包含课程代码、名称、学期、学分等基本信息
- **考试类型**: 假设只有平时、期中、期末三种考试类型

### 1.2 分析假设
- **OBE达成度计算**: 假设达成度阈值默认为60%，可根据课程调整
- **题目难度标准**: 假设难度系数0.4-0.6为中等，0.6以上为容易，0.4以下为困难
- **预警规则**: 假设预警分为一般预警和严重预警两个级别
- **AI分析**: 假设使用DeepSeek API进行智能分析

### 1.3 用户假设
- **用户权限**: 假设有系统管理员、教师、教学管理员三种角色
- **操作习惯**: 假设用户具有一定的计算机操作基础
- **使用场景**: 假设主要用于期末试卷分析和成绩管理

## 2. 技术假设

### 2.1 环境假设
- **Python版本**: 假设使用Python 3.10+版本
- **Node.js版本**: 假设使用Node.js 18.0+版本
- **数据库**: 假设默认使用SQLite，可选择PostgreSQL
- **操作系统**: 假设支持Windows、Linux、macOS

### 2.2 依赖假设
- **FastAPI版本**: 假设使用0.104.1版本
- **Vue 3版本**: 假设使用3.3.8版本
- **Element Plus**: 假设使用2.4.4版本
- **ECharts**: 假设使用5.4.3版本

### 2.3 性能假设
- **数据规模**: 假设单门课程学生数不超过1000人
- **并发用户**: 假设同时在线用户不超过50人
- **响应时间**: 假设API响应时间不超过3秒
- **计算时间**: 假设500名学生成绩计算不超过10秒

## 3. 功能假设

### 3.1 核心功能假设
- **数据导入**: 假设支持CSV和Excel格式，文件大小不超过10MB
- **成绩分析**: 假设支持基本的统计分析和可视化
- **OBE分析**: 假设支持课程目标达成度计算
- **学情预警**: 假设支持基于规则和AI的预警生成

### 3.2 扩展功能假设
- **报表导出**: 假设支持Excel和PDF格式导出
- **AI分析**: 假设支持使用DeepSeek API进行智能分析
- **权限管理**: 假设支持基于角色的访问控制
- **日志审计**: 假设支持操作日志记录和查询

### 3.3 界面假设
- **响应式设计**: 假设支持多种设备访问
- **用户体验**: 假设界面简洁直观，学习成本低
- **图表展示**: 假设使用ECharts进行数据可视化
- **交互设计**: 假设支持常见的Web交互方式

## 4. 安全假设

### 4.1 数据安全假设
- **敏感信息**: 假设学生姓名等敏感信息可以脱敏处理
- **API安全**: 假设使用JWT进行认证授权
- **数据保护**: 假设数据库连接信息等敏感数据加密存储
- **访问控制**: 假设基于角色进行权限控制

### 4.2 系统安全假设
- **SQL注入**: 假设使用ORM防止SQL注入
- **XSS防护**: 假设对用户输入进行验证和过滤
- **CSRF防护**: 假设使用FastAPI内置的CSRF防护
- **速率限制**: 假设对API请求进行速率限制

## 5. 部署假设

### 5.1 部署环境假设
- **服务器配置**: 假设有2核CPU、4GB内存、20GB存储
- **网络环境**: 假设有稳定的网络连接
- **域名**: 假设有可用的域名用于HTTPS

### 5.2 运维假设

- **版本升级**: 假设支持平滑的版本升级
